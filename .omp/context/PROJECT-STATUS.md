# ProviderPriceSwitcher 功能与待办

## 项目目标

在 Windows 上查询多个 OMP 模型供应商的价格，比较各分组单价并推荐最低价 Provider；只有用户明确操作后才修改 OMP 配置并启动新进程。

## 已有功能

### 价格查询与比较

- 支持 New API 站点的公开 `GET {baseUrl}/api/pricing`。
- 精确匹配目标模型、当前分组及模型可用分组。
- 主表已展示：站点、刷新状态、当前组、**最低组**、输入/缓存/输出每百万 Token 单价、更新时间、故障或警告。
- 用量模板功能已移除；当前临时比较基于固定默认用量，后续改为每个分组独立配置具体用量。
- 并发刷新启用站点；单站失败不终止整轮检查。
- 成功结果保存最后快照；失败时保留旧快照并标记陈旧。
- 自动推荐仅采用本轮刷新成功、配置匹配且快照有效的站点；同价优先保留当前 Provider。
- 更低分组只提示，不假定 API Key 具有该分组权限。

### 站点与本地数据

- 支持新增、编辑、删除和启用/禁用站点。
- 本地保存站点设置和最后成功价格快照。
- 支持请求超时、手动价格检查和带默认项的常用 OMP 工作目录设置；历史成功价格不按时间过期。

### OMP 切换与启动

- 从 `config.yml` 的 `modelRoles.default` 识别当前 Provider。
- 目标 Provider 仅来自应用内手动配置的站点，包括已禁用站点，不依赖 `models.yml` 或价格快照。
- 预览并统一替换 `modelRoles` 及 task-agent override 中的合法模型引用，保留模型名。
- 点击“切换并启动 OMP”后直接执行，不再显示确认或结果弹窗；结果写入顶部状态栏。
- 先备份再原子替换配置。
- 通过 Windows Terminal 新标签页在所选工作目录启动 OMP。
- 启动失败不静默回滚已完成的配置切换，错误写入顶部状态栏。

### 已有验证

- Core：综合成本、金额边界、同价选择、历史快照、刷新失败及配置变化失效。
- Adapters：New API URL、价格换算、有效分组交集和最低组。
- Infrastructure：设置与快照持久化、备份、原子写入及损坏数据处理。
- OMP：配置分析、切换和进程相关契约测试项目。

## 当前计费约定

### Ekti：普通服务档

`gpt-5.6-sol` 的公开表达式仅在请求显式设置 `service_tier: "priority"` 时加价。当前 OMP 未设置该参数，因此按普通档计算，不再显示 Priority 警告。

### Code28：短上下文档

`gpt-5.6-sol` 的公开表达式以单次请求 `len <= 272000` 为短上下文档。按当前产品约定，价格比较统一采用短上下文系数，不展示长上下文提示。

刷新状态区分为“成功”“成功（警告）”“失败（旧快照）”；失败旧快照不参与自动推荐。“存在更低分组”是普通提示，不触发行警告色。
