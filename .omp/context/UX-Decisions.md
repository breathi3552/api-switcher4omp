# UX 交互决策

本文是用户交互设计的唯一事实来源。这里记录已收敛的交互行为和明确延后的 UX 方向；不代表延后项目已经实现。生产现状仍以 `Project-Overview.md` 和源码为准。

## 主页面

- 保持现有 UI 骨架：中部为价格检查和价格表，底部为活动供应商应用与 OMP 启动区域。
- 首版继续显示每家供应商的当前绑定分组和最低价分组；两者相同时合并一行，暂不展开其他分组。
- 只有当前绑定分组可应用；最低价分组只读，不代表当前 API key 具备该分组权限。
- 只有当前绑定分组可应用；价格检查完成后选中推荐供应商作为待应用目标，但不改变全局活动供应商。
- 底部按“目标供应商 + 应用供应商”和“OMP 工作目录 + 启动 OMP”分组；两个命令各自保持忙碌状态，互不阻塞。
- 应用供应商改变共享活动供应商，只影响后续新请求；启动 OMP 使用用户选择的工作目录，不改变活动供应商。
- OMP 接管、重复启动和托盘生命周期已分别由 Issue #5 与 Issue #7 收敛；独立运行状态页仍延后，当前主页提供只读网关、活动路由和 OMP 接管状态点。

## 供应商管理

- 一个供应商只有一个业务记录，`ProviderId` 唯一；API key、分组或显示名不充当身份。
- 编辑窗口在同一窗口中分为基础配置、价格查询和模型推理三段；站点访问凭据位于价格查询段，推理 API key 独立管理。
- 基础配置支持可选配置页面路径；空值在首页双击时使用 `Base URL/keys`，非空路径拼接到 `Base URL` 后。
- 价格查询区域包含目标模型、当前绑定分组、当前分组倍率、价格探测操作和站点凭据区域；凭据区域只展示摘要和更新/清除操作。
- 当前版本每个供应商只保留一个推理 API key，该 key 绑定一个当前访问分组。
- API key 与当前绑定分组一次性保存；要么一起成功，要么保留旧值。
- 已保存 key 只显示摘要，不回填原文；关闭、取消或空输入不改变旧 key。
- 删除当前活动 key 或整个供应商时清空全局活动路由状态；生产 loopback 已验证在途请求继续旧 Route Snapshot，新请求不回退且无活动时得到稳定错误。
- 当前只支持 GPT 模型族；OMP 请求的具体 ModelId 原样转发，价格基准模型不等于唯一可调用模型。

## 网关和活动路由

- 使用固定版本的 Bifrost fork，首版只承诺 OpenAI Responses。
- WPF 与 sidecar 使用单一双向 Windows Named Pipe；用户不配置 IPC，也不开放 localhost 管理接口。
- sidecar 按 `keyHandle` 在请求生命周期内取得推理 API key。
- 所有 OMP 共享一个可为空的活动供应商；切换后新请求使用新路由，在途请求继续原路由。
- 不自动应用价格推荐、不自动 fallback、不自动换模型。
- sidecar 断线或协议故障时，用户可见状态与无活动路由状态分离；应用在网关恢复后自动恢复已确认的路由快照，已打开 OMP 的后续请求继续经过同一固定入口。

## OMP 接管与启动

- 第一次接管是 OMP 配置首次授权，不是每次打开软件。
- 首次启动且未接管时，明确说明会备份配置并改为固定本地 Provider；不允许绕过网关仅启动旧真实 Provider。
- 接管后长期有效；真实供应商变化不再修改 OMP 配置。
- 本地 ProviderId 固定且不可配置。
- 关闭主窗口只缩到托盘，网关继续运行；托盘退出时确认停止网关但不关闭 OMP。

## 延后 UX：运行状态页

运行状态页不是设置页，也不是第二个供应商或网关配置入口。它未来可以展示：

- 本地网关实际状态、健康检查时间、有限恢复状态和手动重启。
- 当前活动供应商、当前绑定分组和路由清除原因，但不展示 key、Cookie、Authorization 或敏感 URL。
- OMP 接管状态、固定本地入口和手动重新接管动作。
- 最近一次结构化错误类别、发生时间和日志入口。

进入开发前必须先定义状态查询与恢复的 Application 接口、网关生命周期状态机、OMP 接管迁移契约、状态文案/无障碍文本/托盘通知策略，以及隔离验证方案。

## 端口和迁移交互

- 默认监听地址为 loopback；端口可在普通设置中修改，保存后下次完整启动工具才生效。
- UI 同时显示目标端口和当前生效端口；端口占用时拒绝启动，不随机换端口、不复用未知服务。
- 旧站点升级为供应商配置时保留价格配置、当前分组、价格快照和站点访问凭据；推理 Base URL/API key 默认为空，不猜测或复制旧 AccessToken/Cookie。
- 旧 OMP provider 不自动迁移，首次启动走显式接管流程。
