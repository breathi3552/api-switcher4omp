# ProviderPriceSwitcher 业务实施计划

## 1. 核心业务流水线

```text
加载站点、用量模板与最后成功快照
  → 按设置决定是否启动后自动刷新
  → 并发请求各启用站点公开定价
  → 验证目标模型、当前分组和计费规则
  → 成功站点更新最后成功快照
  → 失败站点保留旧快照并标记故障
  → 使用当前用量模板计算预计综合成本
  → 仅在本轮刷新成功站点中生成推荐
  → 用户确认或改选 provider 与 OMP 工作目录
  → 对陈旧快照或过期检查结果进行风险确认
  → 验证 OMP provider 与配置结构
  → 备份并原子切换配置
  → 启动新 OMP 进程
```

## 2. 已确认业务规则

### 2.1 综合成本

推荐依据不是单一输入价，而是当前用量模板下的预计成本：

```text
预计成本 = 未缓存输入单价 × 未缓存输入 token
         + 缓存读取单价 × 缓存读取 token
         + 输出单价 × 输出 token
```

所有单价先统一为每 1M token，金额计算使用 `decimal`。缓存读取 token 与未缓存输入 token 是互斥计费桶，不重复计算。

默认模板为“Codex 高缓存”：

- 未缓存输入：200,000 tokens
- 缓存读取：800,000 tokens
- 输出：100,000 tokens

用户可以保存和选择多个用量模板。切换模板只重算本地综合成本，不重新请求站点。

### 2.2 刷新、快照与推荐

- 第一版每个站点只持久化最后一次成功价格快照，不保存完整价格历史。
- 刷新成功时覆盖该站快照。
- 刷新失败时保留旧快照，并显示故障图标、原因、快照时间和数据年龄。
- 本轮刷新失败但快照仍与当前站点配置、目标模型及 `currentGroup` 匹配时，站点仍可被用户手动选择。
- 自动推荐只使用本轮刷新成功的站点；陈旧快照不得自动成为推荐项。
- 用户手动选择陈旧站点时，执行前必须确认刷新失败状态与快照年龄。
- 同价时推荐当前 provider。
- 更低分组仅警告；仍按用户已确认的 `currentGroup` 计算，不使用未证实权限的低价分组。

### 2.3 检查结果有效性

- 启动后是否自动刷新由设置项控制，默认开启。
- 价格结果具有 TTL。超过 TTL 后仍允许用户执行，但必须明确确认旧结果，并记录结果时间、过期时长、模板和选定 provider。
- 站点配置、目标模型、用量模板或 OMP 相关配置在检查后发生变化时，旧结果直接失效，不能通过确认绕过。

### 2.4 OMP 切换与启动

- 当前 provider 取自 `modelRoles.default`（键名匹配大小写不敏感，写回保留原键名）模型引用中第一个 `/` 前的部分。
- 执行切换时，将 `modelRoles` 与实际 task-agent override 配置域中的所有合法模型引用统一改为目标 provider，保留 `/` 后的模型名。
- 不修改上述配置域以外的文本。
- 修改前展示受影响条目数量和差异摘要。
- 配置修改必须先备份，再原子替换；失败时原文件保持不变。
- 配置切换成功与 OMP 启动是两个独立结果。启动失败时保留已切换配置，允许重试启动或手动恢复备份，不自动回滚。
- OMP 工作目录从用户维护的常用目录中选择，启动前校验并记住上次选择。

## 3. 实施顺序

### 阶段一：业务核心

1. 定义站点配置、用量模板、标准化价格、站点快照、刷新结果、候选资格、警告与推荐决策模型。
2. 实现综合成本计算、同价保留当前 provider、陈旧快照不可自动推荐等纯业务规则。
3. 为金额精度、缓存 token 不重复、同价规则、失败回退资格和配置变化失效建立行为测试。

### 阶段二：价格刷新

1. 实现 `IPricingAdapter` 与 New API 适配器。
2. 精确解析目标模型、有效分组交集和当前分组倍率。
3. 拒绝无法可靠标准化的复杂计费规则。
4. 并发刷新启用站点，逐站隔离超时和解析失败。
5. 成功时更新最后成功快照；失败时组合旧快照和故障状态。
6. 将配置与快照持久化到 `%LOCALAPPDATA%\ProviderPriceSwitcher`。

### 阶段三：OMP 执行

1. 解析 `models.yml` 中可用 provider。
2. 解析 `config.yml` 的 `modelRoles.default` 和 task-agent override 实际配置域。
3. 生成切换预览，验证所有待改模型引用。
4. 实现备份、临时文件写入、原子替换与失败保护。
5. 实现常用工作目录管理、已有 OMP 进程提示和新进程启动。

### 阶段四：GUI 工作流

1. 主表展示实时/陈旧状态、当前与最低分组、三类单价、综合成本、更新时间和故障原因。
2. 提供检查进度、取消、启动自动检查设置和用量模板切换。
3. provider 下拉框预选推荐项，同时保留符合条件的陈旧快照站点供手动选择。
4. 对旧检查结果、陈旧站点和更低分组分别展示清晰警告。
5. 执行前展示配置差异摘要，再进行切换并启动。

### 阶段五：端到端验收

1. 使用 Ekti、Code28、DeepKey 公开接口验证真实价格解析。
2. 使用临时 OMP 配置副本验证两个配置域的统一切换、备份和原子写入；不得直接拿用户配置做破坏性测试。
3. 验证刷新失败保留快照、陈旧站点不自动推荐但可手选。
4. 驱动 WPF 界面完成“检查 → 推荐/改选 → 风险确认 → 切换 → 启动”。
5. 重新生成 framework-dependent 和 self-contained 发布产物。
