# 能力复用规则

本文件只规定复用原则。具体类型、入口和调用方必须以当前源码、代码智能工具和 `AGENTS.md` 导航到的事实文档为准，不把类名或路径固化在规则中。

## 变更前

- 先定位需求涉及的用例、契约、实现和调用方。
- 先搜索现有能力，再决定扩展还是新增；不得仅因调用位置不同复制同义实现。
- 修改公共符号前查找全部引用、实现和装配点。
- 记录复用结论：复用了什么；若不能复用，说明缺少哪项能力以及新实现归属哪一层。

## 复用原则

- 跨界面业务动作复用 Application 用例，不在窗口或 ViewModel 重做编排。
- 领域计算复用 Core，不在适配器、Application 或 UI 复制价格、金额、推荐和快照规则。
- 外部协议复用对应 Adapter 入口；不要在 UI、刷新流程或 Infrastructure 中增加供应商分支。
- 文件、凭据、进程和系统副作用复用已有 Application 端口及 Infrastructure 实现。
- 用户通知、异步命令、日志和共享 UI 资源复用仓库已有边界，不建立平行机制。
- 测试复用已有 fake、loopback、隔离目录和契约 runner 形态；不要另造验证清单。

## 允许新增

只有在现有接口无法表达需求时才新增实现，并满足：

1. 放入正确层，保持架构依赖方向。
2. 暴露最小、可注入、可测试的契约。

禁止用字符串分支、运行时扫描、静态全局或复制逻辑绕过已有契约。
