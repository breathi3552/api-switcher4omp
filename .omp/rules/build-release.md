# 构建、验证与发布

本文件只规定验证原则。SDK、项目、runner、脚本参数和产物路径必须从当前 `global.json`、solution、工程文件和 `eng/` 清单读取，不在规则中复制。

## 固定边界

- 使用仓库声明的 SDK 和官方/仓库指定入口；不得依赖机器 PATH 的未知 SDK。
- 按仓库定义的验证入口执行；不得以通用测试命令替代自定义 contract runner。
- build、格式检查、runner、smoke 和 publish 默认串行，避免共享产物和外部资源竞争。
- WPF、OMP 和其他外部副作用使用临时 data/root、fake 或 loopback；完成后检查正常退出和无残留进程。

## 影响分级

- 内部重构：构建并运行受影响项目/契约验证。
- 行为或契约变更：运行受影响验证；涉及 UI、OMP 或外部副作用时增加隔离 smoke。
- 跨层、发布候选或用户明确要求：按仓库清单完成完整验证链。
## 证据

验证记录至少说明：影响级别、实际命令或入口、结果、隔离目录、未执行项及原因、真实数据未触及和残留进程检查。成功不能只以“能编译”证明，必须覆盖变更的可观察行为。

## 发布

用户验收所需的发布必须在上行验证完成后执行；发布脚本、SDK、输出目录、清理策略和产物验收条件以仓库当前发布入口为准；失败时停止，不把旧产物当作新产物。
