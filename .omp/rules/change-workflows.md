# 变更流程

本文件只规定变更方法；架构、安全和验证细节分别由对应 rulebook 与当前仓库事实提供。

## 开始前

1. 明确目标行为、影响层、外部副作用和禁止扩大的范围。
2. 读取 `AGENTS.md` 指向的相关上下文、ADR、规则和源码入口。
3. 搜索现有契约、实现、调用方、测试和装配点；确定复用或新增理由。
4. 判断契约是仓库内源码契约，还是持久化、外部 API、跨进程或已发布契约。

## 实施

- 先在正确层建立最小契约，再迁移实现和调用方。
- 变更公共符号时迁移全部引用、注册、绑定和验证。
- 失败、取消、重试、持久化和外部副作用必须有明确状态，不靠异常文本或静默 fallback。
- 清理旧入口、重复实现和无效引用。
## 完成判据

变更只有同时满足以下条件才算完成：

- 目标行为在实际调用路径中成立。
- 所有受影响调用方和装配点已迁移。
- 适用的行为、契约、UI 或副作用验证已完成。
- 没有越层依赖、凭据泄露、未声明副作用、残留进程或真实数据污染。
- 相关上下文、ADR 或质量登记只在事实确实变化时更新。
