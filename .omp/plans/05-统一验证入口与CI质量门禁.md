# 目标

建立一个 canonical `eng/Verify.ps1`，作为本仓库唯一验证入口，并由本地与 GitHub Actions 共同调用。入口必须：

1. 从仓库根目录运行并严格解析用户目录 `.dotnet\\dotnet.exe`，验证 SDK 为 `8.0.423`（允许 `global.json` 规定的 patch roll-forward），拒绝系统 Runtime、缺失 SDK、裸 `dotnet` 和未声明的 SDK。
2. 读取唯一 runner manifest，固定八个 runner 及顺序；manifest 同时定义项目路径、受影响层标签和允许的影响级别。任何 runner 缺失、重复、路径不存在、禁用、顺序漂移或 manifest 与 solution/脚本不一致都必须失败。
3. 按影响级别串行执行：SDK/环境与依赖矩阵自检 → solution build → format verify → 受影响 runner 或完整八 runner；禁止并行 build/format/runner，禁止并行争用 `bin/obj`。`dotnet build`、`dotnet format`、`dotnet run` 均只能通过已解析的 `$dotnet` 变量调用；禁止 `dotnet test`。
4. 提供明确参数（至少 `-Impact`：`Document`、`Internal`、`Behavior`、`CrossLayer`，以及显式 `-Runner`/`-AllRunners` 的确定语义），默认安全地跳过真实 Provider 与 UI 写操作；`CrossLayer` 才要求完整八 runner，`Document` 不跑代码验证，任何隐式降级都失败而不是静默跳过。
5. 在进入构建前校验固定生产依赖矩阵：允许 `Application→Core`、`Adapters→Application+Core`、`Infrastructure→Application+Core`、`App→Application+Adapters+Infrastructure+Core`，拒绝反向引用、`Infrastructure→Adapters/App` 等非法项目引用。矩阵检查必须有可审阅 fixture/自检场景。
6. 建立 Windows GitHub Actions CI：在 `windows-2022` 上只调用 `eng/Verify.ps1`，固定 checkout、SDK/setup 与缓存边界，CI 失败即质量门禁失败；不得把同一验证步骤复制到 workflow 或新增 runner 清单。
7. 记录每一步场景、命令、退出码、SDK、隔离 data/OMP/working root、未执行项及原因、真实 Provider/凭据/UI 写操作未触及和残留进程检查；不得把 token、Cookie、密码或真实路径写入日志/artifact。

不变量：唯一 manifest/唯一入口/唯一顺序；八 runner 不遗漏且不禁用；所有命令串行；SDK 固定；依赖方向不变；`TreatWarningsAsErrors` 下 build 必须零警告；真实 Provider 默认不访问；无真实凭据；无 UI 写操作；不因脚本最终退出码掩盖中间失败；不执行 publish。

# 为什么选择此技术路线

PowerShell 适合现有 Windows/WPF 工程和 `eng` 目录，也能严格控制 `$LASTEXITCODE`、串行顺序、临时 root 与退出码；将所有步骤集中在 `Verify.ps1` 可避免本地脚本和 CI 漂移。JSON manifest 让八 runner 顺序、影响标签和禁用状态成为可审阅数据，依赖矩阵以同样方式可被 fixture 驱动，能直接证明遗漏 runner、禁用 runner 和非法项目引用会失败。

GitHub Actions `windows-2022` 是在未发现既定 CI 平台时的确定选择：它与 WPF、DPAPI、Windows 进程/OMP 行为一致，不需要为 Linux 增加不适用的条件分支；workflow 只负责环境准备和调用 canonical 入口，验证逻辑仍只有一份。严格按 SDK → 矩阵 → build → format → runner 的串行链遵守 `rule://build-release`，避免共享 `bin/obj` 的竞态，也使失败阶段和未执行阶段可观察。影响级别让文档、内部重构、行为和跨层变更各自获得必要而不过度的验证，同时默认关闭真实 Provider 与 UI 写操作。

# 注意事项

- 严禁 `dotnet test`、裸 `dotnet`、系统 `C:\Program Files\dotnet\\dotnet.exe`、并行 build/format/runner、并行写共享 `bin/obj`；所有命令必须通过固定用户 SDK 入口且按唯一顺序执行。
- 不得用 `--skip`、disabled 标志、环境变量或失败吞掉来降低影响级别；非法组合必须 fail closed。完整八 runner 的 canonical 名单只能存在于 manifest，CI、计划06和本地说明不得复制第二份。
- 不得访问真实 Provider 网络、读取真实凭据、写入真实设置/OMP root、执行 UI 写操作或把敏感数据放入日志、异常、CI artifact；隔离 smoke 必须使用临时目录和 fake/loopback，并在结束后确认应用及子进程已关闭。
- 依赖矩阵只保护生产依赖方向；测试工程可引用被测层和替身，但不因此扩大生产依赖。发现非法引用时先失败并修复根因，不得通过反射、复制代码或静默允许绕过。
- 不执行 publish。只有用户明确发布任务时才按 `rule://build-release` 在验证链完成后另行发布；计划06即使调用验证入口也不能因此触发 publish。
- 文档更新以实施完成后的事实为准；未完成的脚本、workflow 或 fixture 不得被文档宣称为已接入。
