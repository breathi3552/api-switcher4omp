# 目标

1. 由 `App.xaml.cs` 的 composition root 创建唯一的、遵守 `--data-root` 的 `ISiteCredentialStore` 实例，并通过最小必要构造链传给站点编辑 UI；`Sub2ApiPricingAdapter` 与 `SiteEditorDialog` 使用同一实例，不允许窗口内部 `new WindowsSiteCredentialStore`。
2. `SiteEditorDialog` 永不调用 `LoadCredential`，永不把 token/Cookie 原文从存储加载到任何 TextBox、ViewModel、日志、异常、JSON、快照、备份或 UI 快照。编辑已有站点只显示 `GetSummary` 的中性摘要和到期/更新时间等允许字段。
3. 凭据输入是一次性、显式动作：用户在本次窗口中输入 token/Cookie 后点击明确的“绑定/更新”；保存成功立即清空输入控件；再次打开不回填。清除必须是明确按钮及确认后的 `ClearCredential`，清除后只显示摘要状态。
4. 更新/清除按 ProviderId 和站点类型校验；绑定/更新只表示写入安全存储，不声称 Provider 认证成功；真实认证仍只由价格 probe/adapter 产生结构化结果。
5. 所有 runner 和 WPF smoke 使用 synthetic secret、fake/loopback、临时 `--data-root`、临时 OMP root 和临时合法工作目录；不访问真实 Provider、真实凭据、真实用户数据或生产 OMP 配置。
6. 迁移完成后删除旧的无参具体 store 路径、原文回填代码和无效引用；不得保留别名、重载、shim、双写或“兼容”分支。计划 03 后续可继续迁移其他构造依赖，但不得改变本计划的安全边界。

不变量：凭据只经 `ISiteCredentialStore` 的安全实现持久化；合成 secret 原文不得进入 `settings.json`、snapshot JSON、备份、日志、异常文本、通知、窗口状态或仓库；UI 只能呈现摘要；没有用户明确操作不得保存、更新、清除或触发凭据副作用；`--data-root` 必须同时隔离 settings、snapshot、logs 和 credentials；无凭据站点、过期摘要和清除后的状态仍可观察且不泄露原文。

# 为什么选择此技术路线

- 复用既有 Core `ISiteCredentialStore` 与 Infrastructure `WindowsSiteCredentialStore`，只把实现实例从已有 composition root 沿必要的 App 构造链注入，符合 `Application → Core`、`Infrastructure → Application + Core`、`App → ...` 的依赖方向，避免第二套凭据存储。
- 让 SiteEditor 只依赖 `GetSummary` 与显式写/清除操作，切断最危险的“存储读取→TextBox 回填”路径；秘密不需要进入可绑定模型、站点配置或普通 JSON，且一次性清空降低 UI 生命周期暴露面。
- 在本计划中只迁移 credential store 所需构造链，避免与计划 03 的全面 composition-root 收敛冲突；clean cutover 删除旧无参实现路径，避免双实例导致 `--data-root` 隔离失效。
- 使用 fake、synthetic secret、临时 data/OMP root 和可观察调用断言，能验证安全不变量而不依赖真实 Provider、真实凭据或生产环境；按 `rule://build-release` 串行验证可同时覆盖跨层契约和 WPF 行为。
